# 打包验证与适用范围

此仓库是已有方法的独立发布，没有在整理时追加训练、改写旧结果或重新选择checkpoint。具体数值见[packaging_validation.json](../provenance/packaging_validation.json)。

## 实际完成的检查

1. **保存结果重算**：读取三seed各512个逐视图记录，重算32系统的AP、PR-AUC、正常误报、条件定位和联合定位，与原报告一致。`python scripts/verify_results.py`可重复。
2. **来源与权重字节校验**：三head、normal basis及原数学模块的SHA与实验快照一致。复制模块没有为打包修改公式。见[origin.json](../provenance/origin.json)与[配置](../configs/stat_temporal_v1.json)。
3. **便携入口数值检查**：在一条原来源系统的relation视图上，用Windows CPU、PyTorch2.9.0、NumPy2.3.5前向。与原GPU保存数组相比，检测分数最大误差6.676×10⁻¹¹，根因证据最大误差1.076×10⁻¹⁰，均低于预定1e−7；模型参数前后hash不变。
4. **无TimeRCD依赖检查**：对相同因果特征，加入幅度很大的随机旧`raw_logit/concat_logit`缓存字段，选定head的检测和定位输出逐位不变。便携入口没有加载TimeRCD。
5. **来源生成器核查**：同一种子重新生成的图和一维标签完全相同；观测数组跨运行环境最大差8.882×10⁻¹⁶。最初的字节相等断言因此失败，随后保留这个差异，改为单独报告数值误差，未改原数组或模型分数。Release提供原始数据；复现报告以原始文件为准。

原单视图生成器检查的硬数值上限为1e−12，模型前向上限仍是1e−7。这两个上限分别针对浮点重生成和已保存模型分数，不把数值近似宣称成逐位相同。

## 重训时的两项环境差异

`tests/check_training_plan.py`另核验三seed的384步shuffle、11,010,048观测曝光、1,794训练参数和保存终点参数hash。Windows的新初始化参数hash与原运行不一致，因此没有声明初始权重逐位重现；在原checkpoint中未更新的cal层已观察到2.98×10⁻⁸末位差。原保存终点hash严格一致，推理使用原终点。训练重新运行要记录自己的初始化hash，不能把种子相同当成权重字节一定相同。

正常基函数的80系统构造流程在本机实跑：图和前缀数组80/80与原清单相同，完整case数组74/80相同，6组不同；未获取这6组原完整数组逐点核对，因此不声称它们只差浮点末位。默认基函数计划准备会严格拒绝不同清单。如确需从当前重生成数据做一个独立重训，必须显式`--allow-regenerated-source`，新旧hash和不同系统均记入计划；它不能冒充原结果的严格数据重放。原基函数权重已完整提供，不影响本模型固定权重评估和统计量头复现。

## 没有声称完成的工作

- 没有在本机重新训练三seed或全部重评32系统；本机仅做低成本打包检查。
- 便携训练入口已按原配对/顺序/损失整理，并提供完整原始训练曲线；跨平台重新训练不保证checkpoint文件字节相同。
- 没有打开250M目标基准或150M锁定集，没有测出新的目标VUS-PR。
- 这个单例检查不能替代所有长度、图结构、缺失值、在线场景的验证。当前接口要求有限观测，无缺失值插补。

`reference/`中的旧实验入口保持原字节，仅供审计。它还引用原消融框架的模块和旧路径；本仓库可运行入口是`scripts/`，不把历史入口误称为独立可运行程序。
