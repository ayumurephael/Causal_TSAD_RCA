# 发布结果：时间统计量模型的收益与代价

本页只讨论`source-v1`的32个独立来源确认系统。不是250M生成基准结果，也不是锁定测试结果。三seed是优化重复，统计单位仍是32个系统。完整逐视图记录在[results/source_v1/runs](../results/source_v1/runs/)，全部逐系统增益与退化在[paired_systems.md](../results/source_v1/paired_systems.md)。

## 1. 默认模型到底达到了什么

| 指标 | 三seed均值 | 含义 |
|---|---:|---|
| AP | 69.0684% | 对每个故障视图的异常时间点做排序，再按系统汇总 |
| 梯形PR-AUC | 68.2749% | PR曲线的梯形积分；不是VUS-PR |
| 正常FPR | 1.2606% | 独立正常case中，超过来源正常99分位阈值的点比例 |
| 条件根因Top‑1 | 64.5833% | 已知真实故障窗口时，根因通道排第一的事件比例 |
| 条件根因MRR | 0.74493 | 真实根因排名倒数的平均值 |
| 检测后联合根因召回 | 46.6146% | 先形成报警段，再对匹配的报警段定位；漏检算失败 |

各seed保留独立阈值和独立权重，**没有挑最高seed，也没有将三条分数曲线集成**。单seedAP为69.45/68.46/69.29%，条件Top‑1为65.10/64.06/64.58%。

正常视图没有正例，其AP不定义，不填0参与平均。故障视图平均异常比例43.35%；它影响PR类指标，不能与稀疏异常的目标基准直接比较。根因仅从有父通道的节点采样；未覆盖源节点故障是明确限制。根因窗口及root标签只进入评估，不进入模型前向。

## 2. 与哪一个对照比较，才能理解提升

| 对照 | 本方法AP差，百分点 | 系统配对95%区间 | 能支持的结论 |
|---|---:|---|---|
| 单点因果证据`full` | +8.439 | [5.082,11.927] | 组合时间统计与学习后，来源平均检测明显改善，24系统升、8降 |
| 固定节点多尺度扫描 | +1.805 | [−0.852,4.356] | 均值更高，但尚未稳定超过强的零训练时间扫描 |
| 同容量`stat_pair` | +1.597 | [0.715,2.481] | 加入同视图时间排序有来源支持，预定检验Holm p=0.01050 |

对`full`的条件Top‑1增量为9.115个百分点，区间[1.910,16.408]。但`stat_pair`的联合检测→定位召回47.222%略高于本方法46.615%。因此“AP和条件Top‑1最高”不等于整个部署流程所有指标最高。

参考同口径TimeRCD检测AP55.486%，不评TimeRCD的RCA。本方法依赖正常DAG，还做case内闭式上下文估计，而原TimeRCD没有这个输入/步骤；不能把这个比较称为相同信息条件下的纯网络架构胜出。TimeRCD权重和推理实现不是本发布包的依赖；其原始结果仍保留在实验仓库。

## 3. 为什么保留这个方法，而没有把所有设计拼起来

- **视图内时间排序保留。**同容量和相同曝光下，`stat_temporal`优于仅正常/异常配对监督；这支持针对故障发生时刻优化，而不是只区分整条正常/异常case。
- **固定边扫描作为局部证据保留，不独占检测。**关系故障上，边扫描比同尺度节点扫描高5.136个百分点，比错配时间的边高10.407个百分点；但全部故障平均AP比节点扫描低3.245个百分点，条件定位低19.010个百分点。正确关系配合有局部价值，不等于纯边模型足够。
- **额外故障类型头不纳入默认模型。**相同检测分数指标下，条件Top‑1降5.295个百分点。未通过的复杂组件不因“更符合因果故事”自动合并。
- **查询工况路由、A/D单独学习校准尚无稳定必要性。**查询路由没有胜过打乱查询特征的对照；A/D校准相对同容量通用校准仅+0.048个百分点，区间跨0。
- **保护TimeRCD路径的因果增量是另一个候选。**相对同容量raw适配AP+1.632个百分点，来源有支持；但它不是本仓库`stat_temporal`模型的一部分，不把两套结果拼成同一模型成绩。

上述完整消融汇总保存在[summary.json](../results/source_v1/summary.json)与[supplementary.json](../results/source_v1/supplementary.json)。它们包含原72臂项目的其他条件，用于解释选择，不能理解为本仓库默认运行72组。

## 4. 必须一起展示的退化

| 范围 | 本方法表现 | 对照与含义 |
|---|---|---|
| 普通背景 | AP76.11%，条件Top‑1 82.47% | 优势主要集中在这里 |
| 平滑背景 | AP62.03%，条件Top‑1 46.70% | 还低于固定节点扫描63.79%/51.56%，慢背景问题未解决 |
| 单点故障 | AP69.81% | 原`full`为76.20%，时间累积有短故障代价 |
| 持续测量故障 | AP61.66% | TimeRCD为67.54%，仍存在互补能力 |
| 最差正常系统 | FPR10.576% | 原`full`最差2.873%；均值约1%掩盖了尾部风险 |

真图/错图分别训练的流程比较为AP69.068%/65.205%，条件Top‑1 64.583%/54.167%。这不能替代“固定同一checkpoint，只换推断图”的因果输入检验；该新诊断尚未取回核验，未加入此发布版。

## 5. 成本、范围与原始审计

统计量头每seed384更新，11,010,048观测标量曝光，5,505,024正常目标答案；三seed总33,030,144与16,515,072。另有先前正常基函数128更新、7,340,032观测曝光。缓存与初末前向不计成优化曝光，完整72臂项目的792,723,456不能写成本单模型训练量。

[2226审计](../results/source_v1/completion_audit_2226.json)和[2229审计](../results/source_v1/completion_audit_2229.json)是**完整原消融项目**的校验记录，部分路径指向原服务器。它们保存历史证据，不是新仓库目录配置。

后续至少需要：固定终点的完整生成开发迁移、原四指标与正常误报尾部、未见机制/长度、根节点故障以及自动检测→定位的核验。当前没有本模型目标VUS-PR，没有真实工业迁移SOTA结论。
